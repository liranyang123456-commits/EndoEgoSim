# M8 实施方案：跨域、大基线与评测协议修正

> 版本：v3.3（2026-08-23）  
> 状态：代码已落地，待按需生成 keyframe 批次 / 建路径索引 / 复评

## 1. 对现有实现的诊断（继续优化的依据）

已完成的 M1–M7 把「参照物可用度」做成了可控真值，并验证了仿真微调有效。剩余短板不在渲染正确性，而在**数据覆盖、评测协议、外观域差**：

| 问题 | 证据 | 后果 |
|---|---|---|
| `n_objects_range` 用了 numpy 开区间 | `(0,2)` 永远抽不到 2；`hard.json` 的 `(1,3)` 抽不到 3 | 动态物体数量系统性偏低 |
| `configs/default.json` 过期 | `deformation.prob=0.5`（代码默认 0.85），缺 organ/marker/flow | 用 `--config configs/default.json` 会 silently 偏离文档 |
| 器械接触压陷未接线 | `instrument_tip` 算了但没传给 `TissueDeformation` | 文档承诺的接触形变从未发生 |
| SCARED 转换缺陷 | `rgb.mp4`+`frame_data` 有 **197 帧位姿**，却只拷了 17 张 jpg；且把 1280×2048 上下立体**整幅压到 512×640**（左右目叠在一张图里） | 图像几何被破坏 + hop 仍约 190mm/帧（SCARED 关键帧本身就大）。应用 `real_refs` 从 mp4 取**左目上半**，并用 `keyframe` 仿真补训练 |
| 微调只看连续窗 / 小 gap | VGGT `arange(a, a+S)`；DUSt3R `max-gap=8` | 从未见过 SCARED 级大基线 |
| GT 掩码硬置零 | M7c：DUSt3R +13.5%、Endo3R +51.4% | 形变像素仍有相对位姿信息，观测饥饿 |
| 真实验证集被拷贝 | `c3vd_converter` / `scared_full_converter` 写 PNG | 违反「路径访问、不拷贝」；C3VD 还被 stride=5 抽稀，无法换协议重评 |
| 运动模糊是各向同性高斯 | 与文档「沿运动矢量」不符 | 外观不够内窥镜 |
| 通用 SOTA 未纳入 π³ | ICLR 2026，Sintel ATE 0.167→0.074 vs VGGT | 基线表缺最新前馈参照 |

## 2. 总体流程（本轮已实现）

```
本地真实数据 (E:/C3VD, E:/SCARED, D:/CholecSeg8k, …)
        │  只读路径
        ▼
 [纹理库 / Reinhard 参照]     [scripts/index_real_datasets.py]
        │                          └─► sim_data/real_refs/*/color_index.json
        ▼
 场景采样 ──► 组织(tunnel|organ) + 物体 + 相机轨迹
              (insertion / orbital / free / retrace / keyframe)
        ▼
 形变(蠕动/搏动/呼吸 + 器械接触压陷)
        ▼
 渲染(针孔 GT) ──► RGB 外观层(色彩迁移/渐晕/桶形/方向模糊/噪声)
        ▼
 GT: T_wc, ΔT, T_wo/T_co, depth, mask, flow, motion_mask, ref_frac
        ▼
 训练: 低参照过采样 + 大基线窗口/配对
 评测: uniform | consecutive | stride | adaptive | sliding(+软掩码)
```

**绝对 / 相对运动真值不变**：世界系=首帧相机系；`T_wc` 绝对、`ΔT_ij` 与 `T_co` 相对。外观层不改几何 GT。

## 3. 新增能力与用法

### 3.1 轨迹

- `retrace`：沿同一中心线进镜再退回（回环/重访）。
- `keyframe`：密采样 insertion 上按 hop∈`keyframe_hop_mm` 贪心抽帧，旋转仍 ≤15°。

```bash
# 大基线批次（建议 seed 从 2401 起，不覆盖已有 2400 条）
$PY scripts/generate_dataset.py --config configs/keyframe.json \
    --n-seq 400 --seed-start 2401 --workers 12 --gpu \
    --out D:/ego_motiion_Camera/sim_data
```

### 3.2 真实数据：路径引用，不拷贝

```bash
$PY scripts/index_real_datasets.py --out D:/ego_motiion_Camera/sim_data/real_refs
# 产出仅 meta / pose_c2w.txt / intrinsics.json / color_index.json
# C3VD 保留全部原始帧；SCARED 指向 rgb.mp4（评测时解码左目到系统临时目录）
```

### 3.3 评测协议（先修协议，再谈崩溃）

```bash
# 旧协议（会放大 hop，仅作对照）
$PY scripts/baseline_sota.py --method vggt --seq "sim_data/real_test/scared_*" \
    --protocol uniform --max-frames 32

# 推荐: 限制相邻平移
$PY scripts/baseline_sota.py --method vggt --seq "sim_data/real_refs/scared_*" \
    --protocol adaptive --max-frames 32 --max-step-mm 12

# 滑窗估计 + Sim3 拼接（长序列）
$PY scripts/baseline_sota.py --method vggt --seq "sim_data/real_refs/c1_*" \
    --protocol sliding --window 16 --window-stride 8

# 软运动掩码（替代硬置零）
$PY scripts/baseline_sota.py --method dust3r --seq "sim_data/test/seq_*" \
    --gt-mask --gt-mask-mode soft --max-frames 32 --scene-graph swin2
```

### 3.4 训练采样

```bash
# VGGT: 混合窗口 + 低参照过采样
$PY scripts/finetune_vggt.py --freeze global --iters 800 --sample-mode mixed \
    --hard-frac 0.4 --stride-lo 2 --stride-hi 6 --out results/finetune/vggt_m8

# DUSt3R: 30% 大基线配对
$PY scripts/finetune_dust3r.py --iters 1500 --large-gap 24 --large-gap-frac 0.3 \
    --hard-frac 0.35 --out results/finetune/dust3r_m8
```

## 4. 与 SOTA 的对应关系

| SOTA 需求 | 本系统对应 |
|---|---|
| MonST3R/VGGT/CUT3R：动态+位姿+深度视频 | 已有；现补大基线窗与低参照过采样 |
| DyEndoVO：运动掩码加权残差 | `--gt-mask-mode soft`（形变×0.25，物体×0.08） |
| SimCol3D：合成位姿难在外观 | Reinhard 序列级色彩迁移 + 渐晕/桶形 |
| SCARED 关键帧 / SurgCUT3R 层次推理 | `keyframe` 轨迹 + `sliding` 协议 |
| π³（无参照视图、排列等变） | 本地尚无权重；接口预留，优先 VGGT/DUSt3R 复评 |
| C3VD-DEFCOL 扩散翻译 | 下一步（未实现）；当前用统计色彩迁移作廉价替代 |

## 5. 建议实验顺序（不自动开训）

1. `python tests/run_all.py` 确认回归。
2. `index_real_datasets.py` 建 `real_refs`。
3. 用 **adaptive / sliding** 复评现有 VGGT/DUSt3R 权重（同一 ckpt，只换协议），看 SCARED 是否仍「崩溃」还是 hop 被协议放大。
4. 生成 `configs/keyframe.json` 400 条并入 train（seed≥2401）。
5. `mixed` + `large-gap` 微调，再在 sim 分层 + real_refs 上复测。
6. `--gt-mask-mode soft` 复做 M7c，预期不再全面变差。
